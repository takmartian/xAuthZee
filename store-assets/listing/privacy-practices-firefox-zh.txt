Firefox Add-ons（AMO）—— 隐私与数据使用规范答案（纯文本）

本文件对应 Chrome Web Store 版本（privacy-practices-zh.txt），按 AMO
上架表单调整。主要差异：

  - 没有 chrome.idle 权限段（Firefox WebExtensions 不支持 idle API）。
    因此系统锁屏立即锁这个特性在 Firefox 不可用 —— 5/15/30/60 分钟
    定时器照常工作。
  - 同步走用户的 Mozilla 账号（Firefox Sync），不走 Google 账号。
  - AMO 的隐私表单问的是「是否收集 / 是否发送 / 是否分享」+「访问
    了哪些数据」，不是逐项权限解释。下面 [AMO 隐私] 段是按 AMO
    表单字段直接组织。


[1. 为什么需要 activeTab 权限]

与 Chrome 版一致。扩展只在用户主动点击工具栏图标或扫描按钮时读
取当前标签页 URL，并在用户那次点击的瞬间截取二维码截图。我们
用 activeTab 而不是 <all_urls> host permission，是为了最小权限
原则：扩展不被动监听任何标签页，只在用户显式动作的瞬间工作。
读当前 URL 是为了「绑定当前网站」功能（在用户访问该站点时把匹
配账号排到面板顶部）以及扫描按钮触发的二维码截图。

[2. 为什么需要 alarms 权限]

与 Chrome 版一致。browser.alarms 调度主密码自动锁定时器。当用户
启用主密码加密并选了自动锁超时（5/15/30/60 分钟或从不），扩展会
注册一个名为 xz-auto-lock 的 alarm，触发时清掉 session storage 里
的派生 key、把锁状态切回 locked。alarms 是浏览器原生调度 API，
比 setTimeout 更可靠 —— 即使 Service Worker 被回收也能触发。扩
展只为这一个用途使用 alarms。

[3. （无 idle 权限段 —— Firefox WebExtensions 不暴露 idle API）

背景：在 Chrome 上，扩展监听 chrome.idle.onStateChanged，只对
'locked' 状态反应 —— 立即上锁。这个事件在 Firefox WebExtensions
里不存在，所以扩展退回到只用自动锁定时器：用户必须等定时器
（5/15/30/60 分钟）到期，session key 才会被清掉。README 的
「Firefox 限制」章节有写。

[4. 为什么需要 scripting 权限]

与 Chrome 版一致。用户点扫描按钮时，扩展调 browser.scripting.executeScript
往当前标签页注入一个内容脚本。该内容脚本显示二维码框选遮罩，让
用户拖框框住页面上的 QR，再用 jsQR 解码。注入是按需的（只在用户
点击后，从不在后台对每个标签页运行），注入脚本的生命周期限于扫
描交互。

[5. 为什么需要 storage 权限]

与 Chrome 版一致，一处替换：sync 通过用户的 Mozilla 账号经
Firefox Sync 走，不走 Google 账号。扩展用 browser.storage.sync 持
久化所有用户数据：账号列表、加密记录、偏好设置。sync 意味着数
据自动出现在用户登录同一 Mozilla 账号的所有设备上，通过浏览器
自身同步机制实现 —— 扩展自己不接触任何外部服务器。扩展还用
browser.storage.session 在解锁期间挂派生主密码 key：session
storage 不同步，关闭浏览器即清。

[6. 为什么需要（或不需要）远程代码]

与 Chrome 版一致。本扩展不使用任何远程代码。所有 JS 都打包在
上传到 AMO 的 zip 文件里。WXT 构建在 build 时静态打包所有源文
件（lib、components、entrypoints）。没有 eval、没有外部脚本的动
态 import、没有 WebAssembly 模块加载、没有从 CDN 或任何外部域名
取资源。打开扩展源码就能看到完整的可执行代码。

[7. 为什么需要 host permission]

与 Chrome 版一致。扩展不申请任何 host permission（没有 <all_urls>，
没有具体域名模式）。我们用 activeTab 权限代替，它只给扩展一次
点击瞬间对当前标签页的临时访问权限。

[8. 单一用途说明]

与 Chrome 版一致。本扩展的唯一用途是 TOTP（基于时间的一次性密
码，RFC 6238）验证码管理：在浏览器里安全存储用户的 2FA 账号
secret、在用户访问绑定站点时弹出小面板显示匹配的验证码、一键填
进页面 OTP 输入框。扩展不做其他任何事。

[9. 数据使用合规声明]

与 Chrome 版一致。本人确认本扩展符合 Firefox Add-ons 项目政策。
扩展不收集、使用、传输任何用户个人数据：所有账号数据存在用户
设备上的 browser.storage.sync，通过浏览器自身的同步机制在用户自
己的设备间同步；扩展自身从不接触任何外部服务器。无埋点、无追
踪、无广告、无崩溃报告、无第三方 SDK。数据不出售也不分享给任何
第三方。


[AMO 隐私] —— AMO「数据使用规范」表单的直接答案

扩展是否收集任何用户数据？

  否。

扩展是否向远程服务器发送任何数据？

  否。

扩展是否与第三方分享任何用户数据？

  否。

扩展访问了哪些数据，存在哪里？

  扩展访问以下数据，全部存在用户本地设备：

    - 账号列表（服务方、账号标识、Base32 TOTP secret、算法、
      位数、周期、绑定域名）—— 存在用户设备的 browser.storage.sync
      里，并通过用户的 Mozilla 账号经 Firefox Sync 复制（这部分
      扩展无法控制）。
    - 主密码加密记录（PBKDF2 salt、verifier 密文、KDF 参数）——
      存在 browser.storage.sync。
    - 主密码错误尝试计数（自上次成功解锁以来的连续错误次数）——
      作为加密记录的一部分存在 browser.storage.sync。
    - 用户偏好（浮层开关、宽松识别开关、禁用站点列表、自动锁超
      时）—— 存在 browser.storage.sync。
    - 解锁期间的派生主密码 key —— 只存在 browser.storage.session
      里，关闭浏览器清掉，自动锁定时器也会清掉。
    - 用户点击时的当前标签页 URL —— 只在内存里读，不持久化。

扩展申请了哪些权限，用来做什么？

    - storage：持久化上面列出的数据。
    - activeTab：用户点击时读当前标签页 URL，用于「绑定当前网
      站」和二维码截图。
    - scripting：用户触发扫描时注入 QR 框选内容脚本。
    - alarms：调度主密码自动锁定时器。
    - idle：响应系统锁屏事件，立即上锁。（这个权限在 manifest 里
      声明但在 Firefox 上无效 —— Firefox WebExtensions 不暴露
      idle API。扩展通过特性检测容忍它的缺失。）
